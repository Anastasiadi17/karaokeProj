# Подсистема C, первая половина: аккаунты и лимит Free — Implementation Plan

**Goal:** у продукта появляются пользователи, вход по ссылке на почту и
работающий лимит Free — без единой строки про Stripe.

**Дизайн:** `docs/superpowers/specs/2026-08-14-accounts-billing-design.md`.
Здесь исполняются пункты 1–6 его порядка задач; биллинг (7–10) идёт отдельным
циклом и в этот план не входит.

**Почему половина.** Пункты 1–6 полезны сами по себе: аккаунты и лимит
работают без платежей. Если Stripe отложится или заменится, ничего из
сделанного не выбрасывается.

## Global Constraints

- **Схема живёт в той же SQLite**, что треки и задачи (решение 1 дизайна).
  Отдельного соединения-на-запрос нет: как и `JobStore`, хранилище держит одно
  соединение и сериализует доступ замком.
- **Пароли не хранятся никогда.** В базу кладётся только хеш одноразового
  токена и хеш токена сессии — утечка базы не даёт войти.
- **Почта на этом этапе — заглушка в лог.** Провайдер подключается в задаче 7
  (биллинговый цикл); блокироваться на нём здесь нечем.
- **Существующие треки без владельца остаются рабочими.** Миграции данных нет:
  бесхозные треки доживают до уборки по TTL.
- Рабочая директория для команд: `api/`.

### Task 1: Хранилище аккаунтов

**Files:**
- Create: `api/src/karaoke_api/accounts/__init__.py`, `accounts/store.py`
- Create: `api/tests/test_account_store.py`

**Produces:** `AccountStore(db_path)` с методами `upsert_user(email) -> User`,
`get_user(user_id)`, `create_login_token(email) -> str` (возвращает сырой
токен, в базу кладёт хеш), `consume_login_token(raw) -> User | None`,
`create_session(user_id) -> str`, `user_for_session(raw) -> User | None`,
`delete_session(raw)`, `count_operations(user_id, since) -> int`,
`record_operation(user_id, kind, track_id)`.

- [ ] **Step 1: Тест на хранилище**

Проверять по одному утверждению на кейс:

- пользователь заводится по email и второй раз не дублируется (`upsert`);
- email нормализуется — `Ivan@Example.COM` и `ivan@example.com` это один
  человек;
- сырой токен входа в базе не лежит (`SELECT` по таблице не находит его);
- токен входа срабатывает один раз: второй `consume` отдаёт `None`;
- просроченный токен не срабатывает;
- сессия отдаёт своего пользователя, чужой токен — `None`;
- просроченная сессия не отдаёт пользователя;
- `delete_session` разлогинивает;
- `count_operations` считает только своё и только после `since`.

- [ ] **Step 2: Реализация**

Схема (в дополнение к существующей, тем же `executescript`):

```sql
CREATE TABLE IF NOT EXISTS users (
    id         TEXT PRIMARY KEY,
    email      TEXT NOT NULL UNIQUE,
    created_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS login_tokens (
    token_hash TEXT PRIMARY KEY,
    email      TEXT NOT NULL,
    created_at TEXT NOT NULL,
    expires_at TEXT NOT NULL,
    used_at    TEXT
);

CREATE TABLE IF NOT EXISTS sessions (
    token_hash TEXT PRIMARY KEY,
    user_id    TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_at TEXT NOT NULL,
    expires_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS operations (
    id         TEXT PRIMARY KEY,
    user_id    TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    kind       TEXT NOT NULL,
    track_id   TEXT,
    created_at TEXT NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_operations_user
    ON operations(user_id, created_at);
```

Токены: `secrets.token_urlsafe(32)` наружу, `hashlib.sha256` в базу. Соли нет
намеренно — токен и так случайный на 256 бит, соль защищает от словаря,
которого здесь не существует.

`PRAGMA busy_timeout` выставить и здесь, и в `JobStore`: две связи к одному
файлу теперь живут в одном процессе, и без таймаута редкое совпадение записей
даст `database is locked` вместо ожидания.

- [ ] **Step 3: Коммит** — `feat(api): хранилище аккаунтов и сессий`

### Task 2: Вход по ссылке

**Files:**
- Create: `api/src/karaoke_api/accounts/routes.py`
- Modify: `api/src/karaoke_api/main.py`, `deps.py`, `config.py`
- Create: `api/tests/test_login.py`

**Produces:** `POST /api/auth/request` (тело `{email}`) → 204 всегда;
`GET /api/auth/callback?token=…` → 302 на `/` с кукой сессии;
`POST /api/auth/logout` → 204; настройки `session_ttl_days = 30`,
`login_token_ttl_min = 15`, `public_base_url`.

- [ ] **Step 1: Тест**

- `POST /api/auth/request` с незнакомым email отвечает 204 и **создаёт**
  пользователя не раньше, чем токен использован;
- ответ 204 одинаков для существующего и несуществующего адреса — иначе
  эндпоинт превращается в проверялку «есть ли такой пользователь»;
- ссылка из лога приводит к 302 с `Set-Cookie`, кука `HttpOnly`;
- повторный переход по той же ссылке даёт 400;
- битый токен даёт 400, а не 500;
- `logout` гасит сессию: следующий запрос к защищённому эндпоинту — 401.

- [ ] **Step 2: Реализация**

Письмо — `log.info` со ссылкой целиком: на этом этапе это и есть доставка,
и в тестах она же служит транспортом.

Кука: `HttpOnly`, `SameSite=Lax`, `Secure` при `https` в `public_base_url`,
срок — `session_ttl_days`.

- [ ] **Step 3: Коммит** — `feat(api): вход по одноразовой ссылке`

### Task 3: Сессия в запросе и `GET /api/me`

**Produces:** зависимость `current_user(request) -> User | None` и

`GET /api/me` → `{email, plan, operations_used, operations_limit}`.

- [ ] Тест: без куки — 401; с кукой — свой email и план `free`;
      счётчик операций растёт после загрузки трека (проверяется в задаче 4).
- [ ] Реализация: план пока всегда `free` — подписок ещё нет, поле
      существует, чтобы интерфейс не переписывался в биллинговом цикле.
- [ ] Коммит — `feat(api): текущий пользователь и GET /api/me`

### Task 4: Лимит Free на загрузке

**Files:** `main.py`, `config.py`, `tests/test_upload_limit.py`

**Produces:** `POST /api/tracks` требует сессию; при исчерпании лимита —
429 `{"error": "quota_exceeded"}`; настройка `free_monthly_operations = 3`.

- [ ] Тест: без сессии — 401; третья загрузка проходит, четвёртая даёт 429;
      счёт идёт по календарному месяцу (операция прошлого месяца не считается);
      операция записывается **после** успешной постановки задачи, а не до —
      иначе отказ по формату съедал бы лимит.
- [ ] Реализация: границу месяца считать в UTC, тем же `datetime.now(timezone.utc)`.
- [ ] Коммит — `feat(api): лимит бесплатного тарифа на загрузке`
